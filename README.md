# 简洗 Jianxi

简洗是一个使用 Kotlin、Jetpack Compose 和 Material 3 构建的独立 Android 洗衣客户端，提供短信登录、扫码识别设备、模式选择、单次支付和本机订单查询，支持自选明暗主题、多组手动配色、桌面壁纸取色、液态玻璃悬浮底栏及普通固定底栏。

[GitHub 源码](https://github.com/xiyuchengxu/jianxi) · [问题反馈](https://github.com/xiyuchengxu/jianxi/issues) · [MIT 开源协议](LICENSE)

当前对外版本 **1.0.1**，内部版本 **0.1.17**，Android 构建号 **18**，支持 Android 8.0（API 26）及以上。包名 `dev.rain.laundry`，可与原平台客户端并存。覆盖升级包沿用测试签名；正式版沿用 1.0.0 的独立正式签名，请使用与手机现有版本相同签名的安装包覆盖升级，详见 [签名说明](RELEASE_SIGNING.md)。本项目与原服务平台无隶属关系。

## 1.0.1 · 玻璃强度与弹性动画

主题页在底栏设置下新增“液态玻璃”，即时应用并独立保存三个等级：

| 等级 | 悬浮底栏效果 |
|---|---|
| 无 | 实色表面，不采样背景、不模糊、不使用折射透镜；保留弹性选中滑块 |
| 轻度 | 柔和毛玻璃，较弱的放大、折射与鼓起幅度 |
| 完全 | 更通透的背景、更明显的折射、色散和液态形变 |

已有设置缺少新字段时默认“完全”。固定底栏始终使用普通 Material 导航栏，不使用玻璃；切回悬浮后恢复已选等级。分组内提供同一渲染器的交互预览，登录前也可试长按、拖动、松手，不会操作实际业务页面。

底栏增加按下压缩、移动拉伸、松手和轻点后的弹簧回弹，形变保留轻微过冲；端点位置受限，避免快速跨页时滑块越出底栏。短按只移动滑块和导航，仍不启动折射透镜。主题选项增加按压缩放与勾选弹出；“配色风格”菜单围绕触发位置弹性展开和收回，并在退出动画结束后再移除。

玻璃模式允许滚动内容经过底栏背后以供取样，列表末尾留出足够空间，保证最后的付款按钮等内容能够滚至底栏上方。“无”与固定模式保留不被底栏覆盖的内容视口。Android 13+ 使用 AGSL 折射；Android 12 使用模糊/放大回退；更早系统使用较实的半透明与放大回退。

两个安装包分别延续各自 1.0.0 的签名。首次确认文案和摘要保持原样，已在 1.0.0 确认过的用户不需要重新输入。登录、订单、支付、壁纸配色与权限未改动。构建结果和设备验证范围见 [VALIDATION.md](VALIDATION.md)。

## 0.1.14 底栏开销与滑动翻页

底栏短按只切换页面和移动选中高亮，不再启动折射透镜；按住约 140ms，或拖动超过触摸阈值后，仍使用原有液态玻璃透镜及回弹效果。模糊效果、渐变画刷会复用，透镜参数完全相同时复用 RenderEffect；透镜变化的重组范围缩小到透镜本身，选中高亮的动画在布局/图层阶段读取，减少底栏标签随动画反复重组。主题页改用带稳定键的 LazyColumn，只创建可见区域及必要预取的分组。

新增三个主页间的左右滑动翻页：向左到下一页，向右到上一页，按“洗衣 → 订单 → 主题”排序，到边缘不循环。横向滑动达到阈值、松手后换页，并同步底栏高亮；纵向滚动由页面滚动容器处理。登录、设备模式、付款确认及请求忙碌期间不启用主页滑动。页面原有的滑动、淡入、无动画选项继续生效，各页滚动位置独立保存。

“主题 → 页面切换 → 左右滑动翻页”开关默认开启、即时生效并自动保存。关闭后继续使用底栏等原有入口换页。

本版提供 `optimized` 非调试安装包，排除 debug 专用 UI tooling，保持原测试签名。没有启用代码混淆或资源删除，避免改变已有账户/订单序列化字段。本轮实际编译与检查、未验证的设备帧率边界见 `VALIDATION.md`；不将代码优化和单元测试通过当作手机掉帧已消除的证明。

## 0.1.13 壁纸取色修正

0.1.12 使用系统生成的动态配色资源；部分定制系统的强调色与壁纸颜色不同，因此会出现紫色壁纸、青色界面的情况。现在优先异步读取 `WallpaperManager.getWallpaperColors(FLAG_SYSTEM)` 返回的桌面壁纸代表色，再通过 Google Material Color Utilities 的 HCT 与 tonal palette 算法生成 Material 明暗配色。选择颜色时优先考虑可见的彩色样本，避免大面积黑色或灰色背景掩盖紫色等壁纸颜色。

动态配色卡片显示实际取到的颜色圆点和状态，并新增“重新取色”。没有获得壁纸颜色时，明确提示“未获取到壁纸颜色，暂用系统配色”，不再将备用系统配色标为壁纸取色成功。系统配置变化、应用回到前台和桌面壁纸颜色变化时会更新取色；只更改锁屏壁纸不会替换桌面壁纸主题。

开关、原有手动色板与纯黑模式继续兼容。功能仍在 Android 12 及以上开放；没有读取壁纸图片、没有新增壁纸或相册权限。Material Color Utilities 仅引入七个必要的 Java 源文件，保留 Apache-2.0 许可，关于页可离线查看。手机系统未提供或未更新正确壁纸元数据时，应用无法保证自动取得壁纸的真实颜色；取色状态和颜色圆点用于确认这项设备兼容性。

构建与回归结果见 `VALIDATION.md`。

## 0.1.12 壁纸动态配色

在主题页的“主题色彩”下面新增“动态配色”分组和“从壁纸取色”开关。Android 12（API 31）及以上使用 Material 3 的 `dynamicLightColorScheme` / `dynamicDarkColorScheme`，直接读取系统生成的配色，不读取壁纸图片、不新增壁纸或存储权限。实现依据 [Android 官方动态配色说明](https://developer.android.com/develop/ui/compose/designsystems/material3#dynamic_color_schemes)。实际颜色由手机的系统壁纸及个性化配色设置提供。

开关默认关闭，升级后保留原有外观。启用后暂停手动色板和配色风格选择，使用系统完整的明暗配色；关闭后恢复先前的手动色板和风格。设置自动保存，兼容跟随系统、强制浅色、强制深色及深色下的纯黑背景。回到应用或系统配置变化时重新读取配色资源。

Android 8–11 显示需要 Android 12 的提示并禁用开关，继续使用手动配色。悬浮液态玻璃和普通固定底栏的实现保持 0.1.11 原样，颜色随主题统一更新。

构建和验证结果见 `VALIDATION.md`。本次没有修改 0.1.10 的登录、报价、下单和付款实现。

## 0.1.10 付款默认值与超时订单恢复

支付宝 App 支付参数省略 `product_code` 时，按[支付宝官方模型的默认值](https://github.com/alipay/alipay-sdk-java-all/blob/master/v2/src/main/java/com/alipay/api/domain/AlipayTradeAppPayModel.java)处理为普通 App 支付，继续核对付款方式、金额及签约内容。显式返回未知产品码时仍停止，并显示经过筛选的产品码供适配。

订单页通过 `order/detail` 核对订单身份与状态。服务端确认订单已关闭后，移除继续付款和取消入口，解除这笔旧单对下一次洗衣的本地限制。取消过程中收到 3122 会再次查询详情；已完成、退款中、已退款也会显示各自状态。没有服务器确认时保留未完成记录。

升级后先在订单页点击“刷新订单状态”，再根据结果重新选择洗衣模式。60 项 JVM 单元测试及 6 项 Android 运行测试通过；模拟器中的支付交付测试在真实 SDK 入口前截获，不代表真实支付宝付款成功。

## 0.1.9 支付渠道机构编号

修正“确认模式，查看金额”后获取支付方式的字段映射：`payChannelRoute/prePay` 中名为 `shopId` 的参数，按原版调用链传入设备的 `orgId`。此前误传设备详情中的 `shopId`，会触发后端将字符串转换为 Long 的错误。

机构编号不符合 64 位整数格式时会提示重新扫码；支付渠道返回错误时会标明“获取支付方式失败”。回归测试使用不同的店铺与机构编号，覆盖完整识别、报价、支付渠道请求链及大整数精度。51 项 JVM 单元测试和 3 项 Android 运行测试通过，真实设备返回仍需覆盖安装后重新扫码验证。

## 0.1.6 报价空值兼容

按原版 JSON 转换器的默认值规则兼容空优惠列表、空选中标记和空类型字段。`options:null`、`participateList:null` 作为空列表处理，避免误报“报价优惠选项格式尚未适配”。已选优惠及非空的异常结构仍会停止确认；格式提示补充字段名和数据类型，不输出字段内容。

## 0.1.5 报价参数修正

修正“确认模式，查看金额”请求：关闭自动优惠使用原版的数值字符串 `0`，补齐所属机构的 `forbiddenPromotions`。普通支付宝、余额下单携带原版明确“不使用金币”的记录，不购买金币、会员或附加商品。

报价返回的优惠列表会区分可选项和已使用项。未选中的优惠目录可以正常展示报价；出现未选择的实际优惠、额外商品或未知选中状态时仍停止确认。回归测试已按原版 APK 的字段约定验证，实际设备需安装后复测。

## 0.1.4 付款顺序与错误提示

新创建、尚未发起付款的订单直接获取支付信息，避免在支付初始化前查询付款状态。继续已发起的支付宝付款时先查询状态，再复用原订单；余额付款结果未知时继续保留订单并等待查询结果。

如果同一订单已在原应用付款，可以刷新状态核对；支付初始化被拒绝时也会查询是否已付款，查询失败会保留原来的错误提示。

付款报错会显示“创建订单失败”“获取支付信息失败”或“查询付款状态失败”等具体步骤，以及服务端错误码。本次修正基于原版 APK 的离线流程核对，真实设备效果仍待空闲时复测。

## 0.1.2 底栏与录屏动效

底栏可见轨道缩为最多 252dp 宽、60dp 高，图标缩为 20dp。参考用户提供的录屏，按住时弹出鼓起的玻璃透镜，拖动时随手指移动并拉伸，松手后落到选中的标签并回弹。拖出底栏较远会取消本次切换。后台请求忙碌时禁用切换，并保留无障碍点击。

透镜单独采样页面和底栏场景，能放大下方的图标及文字，边缘使用折射位移、RGB 色散和高光。Android 13 及以上使用 AGSL；Android 12 使用背景模糊及拖动放大回退；更早版本保留半透明和拖动放大。轨道外预留了透镜鼓起所需的空间。细节见 `GLASS_UI_NOTES.md`。

登录验证码入口已按原版登录页面改为 `common/sms/sendCode`，表单为 `phone`、`template=reg`。0.1.0 错用了 `user/smsCode`，会出现未登录提示。登录前请求使用空会话签名，不夹带残留 token。

同时核对了洗衣流程：模式进入报价前增加 `appoint/checkMachineCanUse` 检查；使用详情接口的正式设备编号及 IMEI；只进入支持的洗衣/洗鞋设备流程；保留支付路由的 `thirdChannel`、`outVoucherId`；区分明确拒单、会话过期、访问受限和结果未知。明确拒单可以重新确认下单，网络导致的未知结果仍阻止自动重试。具体证据与未验证部分见 `PROTOCOL_AUDIT.md`。

使用 Kotlin、Jetpack Compose、Material 3。界面支持自选明暗模式和多组配色；悬浮底栏静止时标签保持清晰，按压时由独立透镜对底栏内容做局部放大和光学效果，也可切换为普通固定底栏。

## 当前功能

- 本人已有账户的手机号、短信验证码登录，发送验证码的 60 秒冷却。
- 本机相机扫描二维码，或粘贴二维码内容；识别 `IMEI`、`SN`、`NQT`。
- 查询设备、选择模式、向后端查询报价、展示本次洗衣项目及金额。
- 使用后端提供的支付宝单次付款或账户余额渠道；不支持微信支付、会员和周期扣款。
- 本机最近一笔订单的保存、继续付款、查询结果、取消未付款订单，以及已付款后的设备同步请求。
- token 和本机订单通过 Android Keystore 的 AES-GCM 加密保存；登出后同一手机号可找回本机保留的订单。

这是根据提供的胖乖生活 1.144.0 APK 静态协议实现的**待实机联调版本**。尚无学校真实二维码与本人账户联调结果，不能把编译成功或单元测试通过当作真实洗衣、支付成功的证明。服务端风控、二维码类型、模式响应结构、新包名与支付签名兼容性仍待确认。

## 使用

安装相应签名的 APK，首次阅读免责声明和用户守则并输入完整承诺后，使用本人手机号登录，再扫描洗衣机二维码或粘贴完整内容。在付款页核对设备、模式和金额，明确点击“确认支付”后才会创建订单。定位权限只在付款前申请，用于原协议下单所需的位置参数；相机权限由本机扫码功能申请。

如果二维码或响应结构尚未适配，客户端会停止该步骤并显示错误，不会使用演示数据替代真实设备。请保留二维码原始内容供后续联调，不要分享短信验证码和登录 token。

## 订单处理

- 报价只接受一个已选择的洗衣项目；出现额外商品或已使用但未选择的优惠时停止下单。可选优惠目录不当作已购买商品。
- 在创建前再次向后端核对报价。金额或项目变动时需要重新确认。
- 创建订单前先保存本地尝试记录。创建请求不自动重试；网络中断导致结果不明时保留“下单结果待确认”，阻止继续创建第二笔订单。服务端明确拒绝下单时显示“下单未成功”，允许重新选择和确认。
- 已知订单的支付宝继续付款复用原订单号。余额扣款请求发出后若结果不明，只查询状态，不重复扣款。
- SDK 返回 `9000` 不直接当作已付款，付款及订单状态通过后端 `order/pay_status` 和 `order/detail` 核对。
- 设备同步请求和“机器已经启动”是不同状态，界面不会把请求发送成功当作已经启动。
- 取消订单先核对详情及付款状态；后端确认取消或详情明确为已关闭时，解除本地未完成订单限制。
- 如果创建请求结果不明且没有拿到订单号，当前版本需要先在原应用核对订单。此版本没有猜测订单号或自行解除这项限制的入口。

## 构建

需要 JDK 17 或 21、Android SDK 35、Build Tools 35.0.0。通过 Android Studio 打开本目录即可；首次构建需要访问 Google Maven 和 Maven Central。

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Windows 使用 `gradlew.bat`。测试 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。源码包不含 Android SDK、构建缓存、账号数据或个人发布密钥。`development-debug.p12` 是随本项目公开提供的开发测试签名，密码为 `android`，用于后续测试版本覆盖升级；它不是正式发布签名，正式发布签名尚未配置。

0.1.14 交付的非调试测试安装包可用以下命令构建，输出为 `app/build/outputs/apk/optimized/app-optimized.apk`。该变体同样使用上述开发测试签名，保留类和字段名，不包含 debug 专用的 UI tooling 依赖。

```sh
./gradlew :app:assembleOptimized :app:testDebugUnitTest :app:lintOptimized
```

1.0.0 的独立正式签名包使用 `:app:assembleProduction :app:lintProduction`，需要按 `RELEASE_SIGNING.md` 提供私有签名环境变量。`BuildConfig.INTERNAL_VERSION` 和 Manifest 内部版本元数据均为 `0.1.16`；系统版本名为 `1.0.0`。

## 协议来源与实现范围

`core/WireProtocol` 实现样本的请求头签名及下单风控签名。协议版本固定为样本的 `1.144.0`，独立客户端版本由 `app/build.gradle.kts` 中的 `versionName` 定义，两者不应混用。签名中的常量来自样本的公开客户端代码，不是账户密码或服务端私钥。

`data/LaundryApi` 仅允许明确列出的必要业务路径，正式主机固定为 `https://userapi.qiekj.com/`。没有关闭 TLS 校验，也不自动跟随业务接口重定向。只有单元测试可向本机 MockWebServer 发请求。

模式数据尚待真实设备验证，目前显式支持返回数组，以及 `skus`、`skuList`、`list` 包装的数组。未知结构直接提示尚未适配。普通洗衣以外的先享后付、免密签约、蓝牙设备、自动续费、会员优惠组合及附加商品不在本版本范围内。已存在的支付平台扣款授权不会因安装本客户端而自动解除。
